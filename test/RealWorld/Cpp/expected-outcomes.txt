# RealWorld C++ corpus (FR-46): the MEASURED outcome of every
# project, one per line, as '<name> <OUTCOME> [blocker-tag]'.
#
# This corpus exists to GENERATE DEMAND for the C++ input subset,
# not to be a conformance target: a REJECTED line is the expected,
# honest baseline and a standing backlog item, not a failure. The
# ratchet is two-way -- a TRANSPILED project that stops
# transpiling fails the gate as a regression, and a REJECTED
# project that starts transpiling fails until it is ratcheted
# forward. The blocker tag is advisory: a changed tag is reported
# loudly but does not fail the gate, since it is a heuristic over
# diagnostic wording.
#
# LIB_BUILT (FR-51) is a project with no 'main': emitrust-cc
# emitted a LIBRARY crate and that crate compiled. It ranks
# between REJECTED and TRANSPILED and is deliberately NOT the
# same as TRANSPILED -- a library has no entry point, so it was
# never RUN and never diffed against a native build. LIB_BUILT
# says the project translates and type-checks; it says nothing
# about whether it computes the right answers.
#
# The trailing '# ported k/n' comment is FR-44's per-item score,
# advisory here and ignored by the parser: the AUTHORITATIVE
# per-item ledger is each project's own expected-items.txt, next
# to its sources. It is repeated on this line so the manifest
# reads as a ranked backlog -- a REJECTED project at 6/8 items is
# a very different backlog entry from one at 0/40.
#
