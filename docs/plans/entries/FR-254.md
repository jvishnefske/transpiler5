- [ ] FR-254 (opened 2026-11-01, child of FR-249): **BX NORMALIZER SEARCH -- arbitrary C++
  -> the Kernel subset (design; seam lands in FR-250).** Rules are Rule(pattern, guard,
  apply), source-to-source over Surface IR: auto -> explicit type, [=]/[&] -> explicit
  capture lists, iterator loops -> index/range-for, `it = find(..)` -> contains/position,
  std::cout -> printf. Search: bounded best-first (A*) over rule sequences, cost = residual
  count + rewrite size, dedup by Kernel hash. EVERY rule is validated twice: a property test
  on generated programs AND the native byte-diff of before/after C++, so the search cannot
  introduce a behaviour change the oracle would not see. HYPOTHESIS, permission to refute:
  that a small rule set covers most residuals in Cpp17Suite/CppStdSuite -- measure the

  MEASUREMENT 2026-11-01 (pre-spike; bx 3fe63ca, pinned woff2+brunsli, 340 observed
  functions, EMIT 18 -- unchanged by FR-252/263, as expected). The observed blocker-count
  histogram is 0:18, 1:33, 2:78, 3:49, 4+:162, so a ONE-rule normalizer can reach at most the
  33 one-blocker functions. Their sole blockers:
  - non-canonical `for` (9): `for (; n >= 128; n >>= 7)`, `i += 4` stride, `--i` / `i != 0`
    descending, step-less `for (..; i < n;)`, `for (..;; c *= 2)`. Every one is covered by ONE
    sound rewrite, `for (I; C; S) B` -> `{ I; while (C) { B S; } }`, valid iff B has no
    `continue` bound to this loop.
  - `x[(*p)++] = v` / `return d[(*p)++]` / `*(d++) = v` (5): post-increment through a pointer
    used as an index. Rewrite to a read, a separate `++`, then the use. Sound iff `v` and the
    base do not mention `*p` (the same rule as FR-259's unsequenced check).
  - do-while (1): `while (true) { B if (!C) break; }`, sound iff B has no `continue`.
  - call to library function (6): NOT normalizer work. These are the projects' header helpers
    (`Store16`, `StoreU32`, `Log2FloorNonZero`, `GetPopulationCountPrecision`) and
    `BRUNSLI_DCHECK`'s abort hook. That is FR-262 header visibility (it corroborates that
    spike).
  - rest (12): globals, enumerators, extern "C", overloading -- Kernel features, not
    rewrites.

  (every Reject golden unchanged; OFF runs pinned in both new lit files).
  WHAT THIS ENTRY GOT WRONG: "valid iff B has no `continue` bound to this loop" is
  INCOMPLETE. Splicing S (or R2's C) after B's statements captures any name B declares at
  its top level: `for (int i = 0; i < n; i += k) { int k = 100; .. }` would step by 100.
  A MEASURED miscompile (the generated-program byte-diff caught it when the guard was
  disabled: g4(17) = 4175 vs 1385); the rule now keeps `{ B }` nested when S / C names
  anything B declares. `break` and `return` need no guard (confirmed: both forms skip S).
  Guards that refuse, located at the loop: a `continue` bound to the loop (found through
  `switch`, not through nested loops or lambdas), a `for` condition variable.
