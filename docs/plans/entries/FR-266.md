- [x] FR-266 (opened 2026-11-03, from FR-267's spike): **BX PHANTOM EMIT ON USES: a use of a
  rejected struct is a located cascade residual.** The per-function census (bx-frontier)
  counts a function as EMIT when it carries no located diagnostic. FR-262 closed this for
  out-of-line DEFINITIONS of a rejected class; USES stayed open: on
  `struct S { int get() const; int x; int* p; }; int user(const S& s) { return s.get() + s.x; }`
  bx reported the struct, the `int*` member and `S::get`, and nothing in `user`, so `user`
  counted as translatable. Nothing miscompiled (the run as a whole fails); the defect is in
  the measuring instrument, and it goes live as soon as header classes import (FR-267). A
  struct holding a rejected struct BY VALUE (directly or as a std::vector element) was also
  silently accepted.

  RULE (cxx_import.py `reject_containing` fixpoint after the struct shells; `struct_use`,
  `rejected_struct`, `rejected_owner`): every use of a rejected struct inside a function --
  parameter, return type, local, data member access, member / static member call, aggregate
  init, constructor call -- gets `use of a rejected struct 'P'` (P the absolute path) at the
  use. It is ADDITIVE: the residual is recorded on a per-function side list and the
  expression is imported exactly as before, because the first version REPLACED the
  expression and hid real blockers on the frontier (woff2 ReadWOFF2Header lost `std::vector::
  resize without a fill value`); pinned by test_use_residual_is_additive_and_hides_no_blocker.
  A containing struct is rejected at the member with the same wording. When no struct is
  rejected the check set is empty, so accepted programs cannot move.

  CENSUS: needle `^use of a rejected struct` -> `struct: use of a rejected struct (cascade)`
  (sub `struct:<path>`). The generic `struct: member` bucket is SPLIT into one tag per reason
  (private or protected member, default member initializer, const / static data member,
  user-declared destructor, nested class, enum inside a class, overloaded constructor, ...),
  so the frontier can rank struct rows -- FR-267 had to classify raw reasons by hand. The
  rejected-member / rejected-aggregate tags are now marked `(cascade)`. Nothing pinned the
  old tag strings except historical frontier/PMF reports, left as records of their runs.
