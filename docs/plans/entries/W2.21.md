- [x] W2.21 `std::unique_ptr<T>` -> `Box<T>`, `std::make_unique` ->
  `Box::new`. Spike verdict **GO-WITH-CONSTRAINTS** (2026-08-21).
  NULLABILITY, the wave's central design question, resolved as a COST
  decision rather than a correctness one, because BOTH images measured
  byte-diff clean: a hand-driven `Option<Box<T>>` image reproduced the
  entire nullable surface (default-ctor, `== nullptr`, `(bool)p`, `!p`,
  `if (p)`, `reset()`, `reset(new T)`, reassign-over-live, `= nullptr`)
  byte-for-byte, INCLUDING the C++17 P0145R3 order -- `ctor 4` printed
  before `dtor 3`, because Rust assignment drops the old value after
  evaluating the RHS. It was still rejected for this wave: it forces
  `(**Option::as_ref(&d).unwrap())` at every deref that a non-null
  program never needed. So the shipped image is bare `Box<T>` over the
  always-initialized subset, FOLLOWING FR-99's precedent ("the local
  stays the bare struct") rather than diverging from it, with every
  nullable shape a LOCATED rejection whose wording states the reason:
  `a Box<T> cannot be null, so ...`. `Option<Box<T>>` is measured-viable
  and is the natural W2.21b.
  THE WAVE-RESHAPING MEASUREMENT: the W2.17 destructor gates are NOT
  unique_ptr-specific. `std::vector<int>`, shipped back in W2.3,
  produces BYTE-IDENTICAL wordings in all six positions -- member,
  parameter, return, global, array, bare block. So W2.21 deliberately
  does NOT touch `userDeclaredDestructor`: unique_ptr inherits exactly
  the local-only boundary vector/string/map already live under, the
  existing wordings are accurate and golden-pinned, and returning a
  `unique_ptr` is out for the same reason returning a `std::vector` is.
  The bare-block rejection is correct for `Box` and comes free. This
  turned a large-looking wave into a small one.
  THE ACCESS-SURFACE SPLIT IS LOAD-BEARING, and it is what avoids a
  measured E0502: `p->m()` and `(*p).m()` lower to `emitrust.method_call`
  DIRECTLY on the Box place (Rust auto-deref renders `p.node_bump(2)`),
  while `p->field` and a scalar `*p` lower through an
  `addr_of` -> `Deref`/`DerefMut` `call_opaque` -> `deref` chain, because
  `MemberOp::verify` requires a StructType lvalue. Building the
  receiver's `&mut` before the argument values -- which is what a
  uniform deref-chain would have done -- makes `p->bump(p->get())` fail
  with "cannot borrow `*p` as immutable because it is also borrowed as
  mutable". Field WRITES take `DerefMut` and depend on the RHS-first
  evaluation order W2.20 had just landed.
  NO NEW DIALECT OPS: `MethodCallOp` already accepts an opaque receiver,
  and the place chain is `emitStlMapEntryPlace`'s W2.20 pattern verbatim.
  Hand-written IR round-trips byte-stably through `emitrust-opt` and
  renders Rust that byte-diffs clean against the native.
  TWO EMITTER DEFECTS WERE PREREQUISITES, each with a measured failure:
  `methodCallMutatesReceiver` fell through to a CLOSED STL name set for
  an opaque receiver, so a `Box<Node>` with a user method name answered
  false and the binding rendered without `mut` (E0596 -- one probe only
  escaped because an unrelated `addr_of mut` forced it); and the
  default-value table had no `Box<` row, so an unread `Box<Guard>`
  binding died at translate time.
  A SILENT-ADMISSION HOLE had to be closed BEFORE unique_ptr could
  return an opaque type: `rustSpellingForElementType` admits ANY
  spellable element, so the moment `unique_ptr` became opaque,
  `Vec<Box<T>>`, `Option<Box<T>>` and `pair<int, Box<T>>` would all have
  been admitted with ZERO spike coverage. `std::array` additionally
  dodges the destructor gate because `userDeclaredDestructor` strips
  clang array types, not `std::array`. A container-element screen ships
  with the wave.
  Twenty-eight wordings, sixteen ledger rows mirrored into
  `RejectionLedger.cpp` AND `test/RealWorld/run_realworld.py`.
  `shared_ptr`/`weak_ptr` get their own wording naming the reason (Rc/Arc
  have different aliasing and this subset has no model for shared
  ownership) instead of sitting on the generic tail.
  Gates: full meson suite 721/721 (fast 515 + slow/EndToEnd 206), 0
  failures. Cpp17Suite ratchets 29 -> 30 (`01007.cpp`) at
  `total=33 transpiled=30 passed=30 miscompiled=0 unsupported=3`;
  CTestSuite 220/220/0/0 unchanged. The EndToEnd leg was confirmed a real
  oracle, not a cache no-op (the crate recompiled, the native rebuilt,
  the diff was empty), and it observes drop timing including
  reverse-declaration order.
  KNOWN GAPS, recorded not silent: `p->id = p->tag;` yields a rustc
  E0502 rather than a located rejection -- fail-loud, but UNPINNED, so a
  future change could silently turn it into emitted-but-wrong code; it
  deserves a rejection pin. `p.swap(q)` is expressible via
  `std::mem::swap` but was not byte-diffed and stays out. And one
  divergence INHERITED from W2.17 rather than introduced here: the
  two-step `Box::new(T::default()); p.ctor(args)` means a DIVERGING
  constructor ARGUMENT would drop a default-constructed payload where
  C++ never constructed one -- identical to today's
  `let mut a: R = R::default(); a.r_new(f());`, and unmeasured in both.
