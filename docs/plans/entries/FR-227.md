  **THEY DO NOT SHARE A FIX. The cohort fragments 1 / 1 / 7**, and saying so
  is the point of this entry:
   - **`crc16` alone is cheap**: ONE const pointer plus a DECLARED LENGTH
     parameter. FR-202's CLASS 2 cannot take it, correctly, because that class
     proves a CONSTANT bound out of the body and this bound is a runtime
     argument. The emitted body makes the pairing visible --
     `pub fn crcish(d: &[u8], v0: u32, ...)` with `for i in 0u32..len { d[i] }`
     -- so every index into the slice is provably `< v0`. That supports a
     **CLASS 2b, the PARAMETER-BOUNDED slice**: the wrapper takes `*const u8`
     plus the existing scalar and builds `from_raw_parts(d, v0)`. Sound on
     exactly FR-202's own argument, generalized from a constant to a
     parameter: a C program that reads `d[len-1]` must already give `d` that
     many elements or it has UB of its own. **Worth +1 case. Filed at that
     size deliberately** -- it is a clean class, not a lever.
   - **`bitwriter_add` reaches CLASS 1 and is refused on FAITHFULNESS**, not
     on arity: "a pointer to 'TflacBitwriter', whose layout model is not
     ABI-faithful" -- the struct carries a pointer member the importer emits
     as an i64 cursor. A different and harder problem; FR-181 already refused
     it for this reason and was right.
   - **The other SEVEN take two or more reference parameters.**
  **THE WALL, MEASURED: 67 CASES, 27% OF THE CORPUS.** Seven clean-emitting
  organic cases plus SPHINCS+'s `prf_addr`, `gen_message_random` and
  `hash_message` at 20 configs each. Every one is FR-181's HARD NO-GO, which
  is not a gap but a **measured miscompile**: two `&mut` built from C pointers
  a caller may legally alias, `kernel(a,b)` with `a == b` returning 10 against
  the clang native's 104, exit 0, no diagnostic.
  **AND FR-222's MUTABILITY INSIGHT DOES NOT RESCUE THEM, WHICH I CHECKED
  BEFORE ASSUMING IT WOULD.** FR-222 established that two SHARED borrows of
  one object are not a hazard and lifted that refusal for CALLS. At the export
  boundary the same reasoning applies -- and **exactly ONE of the 67 has an
  all-shared signature**, `hdr_compare(const uint8_t *, const uint8_t *)`.
  Every other one carries at least one mutable pointer, and **one `&mut`
  aliasing one `&` is UB precisely as much as two `&mut`**, so the insight
  stops at the first output parameter. The mutability-aware relaxation is
  worth at most 1 case here, not 67.
  **WHY A C POINTER NEVER REACHES THE ARITY CAP AT ALL** (FR-226, verified
  again here by probe): `f(const uint8_t *a, const uint8_t *b)`,
  `f(uint8_t *a, uint8_t *b)` and `f(const uint8_t *d, uint32_t len)` ALL get
  FR-139's generic "not all-scalar" sentence, because a C pointer parameter
  imports as a SLICE and the `sliceCount != 0` branch fires before any class
  analysis runs. So the arity cap's careful wording is not even the diagnostic
  these shapes receive -- another instance of a refusal whose sentence does
  not describe the thing refused.
  **WHAT IS AND IS NOT A WAY OUT, so nobody re-derives this:**
   - `restrict` IS the language-level escape -- it is precisely C's promise of
     non-aliasing, and `&mut` from a `restrict` pointer is sound. **None of
     the 67 declare it.** Honouring it where it appears is correct and cheap
     and buys nothing on this corpus.
   - Raw pointers throughout the callee would work and costs `unsafe`, which
     the rubric scores at zero. Not a solution, per FR-224's doctrine that a
     binding relocating an obligation has not discharged it.
   - Copy-in/copy-out through owned buffers is sound against aliasing and
     **semantically WRONG**: C's behaviour when the buffers really do overlap
     is defined, and staged copies do not reproduce it. This is FR-201's
     finding in the other direction and it must not be tried.
   - The index-based single-region model (FR-201, `split_at_mut`) IS sound and
     is what fixes the INTERNAL calls -- but it does not cross the C ABI,
     where the two pointers arrive as genuinely separate arguments.
  ACCEPTANCE: this entry implements nothing. Its claim is a CEILING: without
  overturning FR-181 -- which has a measured miscompile behind it and should
  not be overturned on argument alone -- 67 corpus cases are unreachable, and
  the honest ordinary-cohort target is the 83-case remainder identified in
  FR-225 minus this overlap. Anyone planning export work should cost it
  against these numbers first.
