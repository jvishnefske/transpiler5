- [x] FR-217 (opened and LANDED 2026-09-09; implements FR-215's second
  recommendation): **THE STRING TABLE LOWERS TO THE PADDED 2-D FORM AT NET
  -100 -- BUT THE FENCE IS THE VALUABLE PART, AND IT IS ~9x MORE LOAD-BEARING
  THAN THE SPIKE ESTIMATED.**
  `static const char *const t[N] = {"a","b",...}` now lowers to the
  already-supported padded `[[i8; W]; N]` form. No new op, no new type, no
  dialect change -- the emitter produced that shape already; what was missing
  was the recognizer. Hooked into `createGlobal` ahead of the `mapType` that
  produced the old rejection, so function-local statics come free.
  **THE NULL FENCE FIRED ON 28 REAL SYSTEMD TABLES, NOT 3.** FR-215 named
  three (`virt.c:167`, `catalog.c:31`, `pager.c:304`). The real set includes
  `sigchld_code_table`, `sigsegv_code_table`, `sigill_code_table`,
  `sigfpe_code_table`, `sigbus_code_table`, `sigtrap_code_table`,
  `sigpoll_code_table`, `sigsys_code_table`, `sched_policy_table`,
  `dmi_vendors`, `rlmap`, `versions`, `string_bits` and more. **Every one is a
  deliberate gap whose entire point is that the slot reads NULL** --
  `sigchld_code_table[0]` is empty because SI code 0 is unused. Padding NULL
  to `""` flips `!!table[i]` from false to true, so **without this fence those
  would have been 28 silently wrong programs.** The fence is located at the
  offending element (falling back to the declaration for a designated-init
  hole, since an unlocated rejection is not a rejection) and covers explicit
  `0`/`(void*)0`, the sentinel-terminated idiom, C99 6.7.8p21 zero-fill of a
  short initializer, and a designated gap. A companion rejection keeps a row
  out of any pointer-value context (`while (t[i])`, `t[i]==t[j]`,
  `strlen(t[i])`), because the padded rows have no addresses.
  **A POPULATION CORRECTION TO FR-215:** its classifier undercounted the
  DOMINANT form. A source census finds **421 designated enum-indexed tables**
  (`[LOG_TARGET_KMSG] = "kmsg"` -- systemd's `DEFINE_STRING_TABLE_LOOKUP`)
  against only 15 plain positional ones. Clang resolves designators to
  positional slots before the importer sees them, so they are admitted; the
  shape is now in the byte-diff test.
  LEDGER, paired over a self-pinned 501-unit population: **distinct blocked
  21,089 -> 20,989, NET -100** (107 resolved, all of them `pointer type
  outside a parameter position`; 7 newly surfaced, all the NULL fence; 21 more
  stayed blocked but moved to the specific NULL wording). Ported globals
  298 -> 399. **Contrast FR-215's costed `void*` increment, which measured NET
  +4** -- this is the one that moves the right way.
  **THE BYTE-DIFF CAUGHT A DIVERGENCE IN THE FIRST DRAFT**, which is worth
  recording as the one semantic difference padding makes: reading PAST a short
  element's terminator is UB in the pointer form (each literal is its own
  object) but reads as 0 in the padded form. The native printed adjacent
  `.rodata` (`115, 116`) where the crate printed `0`. Not a miscompile of a
  conforming program, but the test must not depend on it, and it is documented
  in the test comment.
  **A NUANCE THE SPEC HAD SLIGHTLY WRONG, corrected here:** `sizeof` folds
  from the CLANG AST TYPE, which is still `const char *const[N]`, so it emits
  `N*8` -- the same number the clang native prints. It does not *change*; it
  becomes a number that no longer DESCRIBES the emitted storage (`N*W`).
  Rejecting is still right, because a memcpy or write extent computed from it
  would be wrong. `sizeof(t)/sizeof(t[0])` and `/sizeof(*t)` fold to the
  constant N *ahead of* the fence and are pinned as a positive CHECK --
  verified specifically, since rejecting the ELEMENTSOF idiom would have
  gutted the feature.
  STORAGE COST, re-measured and stated because users see it: 101 admitted
  tables go **5,096 B of pointers -> 11,214 B padded, +6,118 B (2.20x)** --
  reproducing FR-215's 2.22x. Widest is `IMAGE_SEARCH_PATH: [[i8; 108]; 4]`,
  432 B for 4 pointers. A 1 MiB per-table cap refuses a pathological blowup
  with a located diagnostic; 0 systemd tables hit it.
  DELIBERATE TIGHTENINGS beyond the brief: the shape gate requires a CONST
  pointee, because `char *const t[] = {"a"}` was admitted and then failed at
  the op verifier with a NON-located error rather than a rejection; and
  `sizeof(t[0])`/`sizeof(*t)` are fenced alongside bare `sizeof(t)`.
  Gate **1031/1031**; clippy 57 -> 57 (+0) at the epoch-7 pin; binding both
  axes flat (free_temps 2307, p95 5); both corpus ratchets unmoved with
  manifests untouched; **TRACTOR 41/252 -- exactly the +0 FR-215 predicted
  structurally.** Golden movement: 720 byte-identical, 360 rejected by both,
  **0 MOVED**, 2 newly admitted and both are the new tests -- and the full lit
  suite was run alongside the sweep, per FR-167's warning that a hash sweep is
  blind to `split-file` sub-units.
