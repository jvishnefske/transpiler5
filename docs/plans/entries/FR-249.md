  PATH, IN PYTHON OVER `clang -ast-dump=json`.** Umbrella for FR-250..FR-254. The existing
  importer lifts lambdas to free functions (no closures, no by-ref capture, no lambda as an
  argument -- ImportCStatements.cpp emitLambdaLocal), has NO `<algorithm>` support (falls
  through to the system-header rejection), ~8 vector methods and a handful of string ones.
  This path shares no code with lib/ImportC. Design: one small typed KERNEL IR; every Kernel
  construct has exactly one canonical C++ spelling and one canonical Rust spelling; four
  functions (cxx_import, cxx_print, rs_parse, rs_print). BIJECTION LAWS, the acceptance
  oracle: (1) parse(print(k)) == k on both sides for every well-typed Kernel term; (2)
  print(parse(x)) idempotent; (3) native clang++ vs cargo stdout byte-identical in BOTH
  directions (C++ input -> Rust, Rust input -> C++); (4) everything else is a LOCATED
  `unsupported:` rejection. The parsers DEFINE the subset. Zero `unsafe`, including the
  emitted runtime helpers. Expected TRACTOR yield: **+0** (the corpus is C) -- this is a
  C++ capability increment, not a TRACTOR one, and every child entry must say so.
