- [x] FR-252 (opened 2026-11-01, child of FR-249): **BX closures.** Explicit all-copy
  captures <=> `move |a: i32| -> i32 {..}`; explicit all-ref captures <=> non-move closure;
  `mutable` / mutating ref capture <=> `let mut f` (FnMut); template `F` params <=> `impl
  Fn`/`impl FnMut`. Capture kind from the closure record's FieldDecl types, explicitness
  from source text (FR-249 spike (b)). Default and mixed captures are outside the Kernel and
  get located rejections NAMING the normalizer rewrite that would fix them (FR-254).
  ACCEPTANCE: every row round-trips and byte-diffs both directions; alias check rejects
  mutation of a container a live ref-capturing closure borrows. Expected TRACTOR: +0.

  LANDED 2026-11-01 (feat/tractor-yield). Kernel `FnT`/`Closure`/`ClosureCall`; both
  printers, both parsers, checker, and a `gen.py closures=True` population (seeds
  6000-6007, ~960 closures; laws 1-2 on both sides, rustc borrow-checks every printed
  program). Rows: `[k]` <=> `move |..|`; `[&acc]` <=> non-move; `template <typename F> R
  g(const F& f, ..)` <=> `fn g(f: &impl Fn(..) -> R, ..)` and `F& f` <=> `&mut impl
  FnMut`. N23: the capture list is NOT in the Kernel; both printers derive it from the
  body in first-use order (written order and unused captures are spellings). N24: a
  `move` closure with no capture prints non-move. EVIDENCE: 4 C++->Rust EndToEnd byte-diffs
  (bx-closure-{capture,template,containers,control}), 3 Rust->C++ (bx-rs/closure-{basic,
  fnmut,generic}), test_fr252.py (19), BX Roundtrip/Reject goldens, no-unsafe-fr252. pytest
  246 -> 265; fast suite green. Independent verification probe (not committed): `[k]`
  modified between calls, `&&`-sequenced double call of a state-modifying closure, unsigned
  wrap in a capture, a `mutable` lambda advanced through `F&` twice -- C++ (ASan/UBSan),
  emitted Rust, and the C++ printed back from that Rust agree byte-for-byte; Rust side:
  moved String => `[name, k]`, FnMut push => `[&v]`, byte-identical; use-after-move-capture
  and use-while-FnMut-borrowed both refused located. Census: 20 FR-252 needles in
  scripts/bx-census.py (every wording the Reject tests produce classifies; the dead `auto:
  lambda` needle removed). Expected TRACTOR: +0 (C corpus); woff2/brunsli EMIT not
  re-measured (closures are rare there).

  WHAT THE ENTRY GOT WRONG. (1) "`mutable` / mutating ref capture <=> `let mut f`"
  conflates two things: `mutable` is exactly "by-copy AND modifies its copy"; a by-ref
  closure that modifies state is FnMut with no `mutable`; `let mut f` is additionally
  required whenever the closure is passed as `&mut impl FnMut` (else E0596). (2)
  "template F <=> impl Fn" is exact ONLY by reference: by-value `F f` copies a mutable
  closure's state in C++ but borrows it in Rust -- refused, normalizer named. The C++ side
  learns the signature only from instantiations, so an uncalled Rust generic is refused.
  (3) MISSING, and a silent miscompile without it: a call of a closure that modifies a
  by-ref capture IS that modification for every analysis (`for (i < n) { shrink(); }`
  would otherwise become Rust's evaluate-once `0..n`; same for `v.size()` bounds and
  range-for invalidation). (4) MISSING: unsequenced double calls of a state-modifying
  closure (`cnt()*10 + cnt()`, two printf arguments, `f(f(1))`) are refused; `&&`, `||`,
  `?:` sequence and stay accepted. (5) Mixed `[k, &acc]` is not just "outside the Kernel"
  -- the Rust `move` spelling silently prints `0 100` against C++'s `9 100`; refused.
  NARROWED (located refusals): by-value `F f`, member-function templates, >1 callable
  parameter, non-scalar closure params/results, nested closures, closures in containers.
  OPEN, PRE-EXISTING (not FR-252): the subset accepts calls with side effects in
  unspecified-order positions, e.g. `printf("%d %d", g(3), g(4))` with printing `g` --
  g++ prints `g4 g3`, clang and Rust `g3 g4`; the clang oracle cannot see it. Needs an
  effect analysis over all functions. -> FR-263 (landed: printing calls only, which is
  the one observable effect).
