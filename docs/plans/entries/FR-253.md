  WHAT THE ENTRY GOT WRONG. (1) "f64 sort via bx::sort_by_less" and "max_element on f64
  via a first-wins helper": both REFUSED. One C++ spelling must have one Rust spelling, and
  a comparator-less f64 sort has no comparator to print; libstdc++ std::sort and Rust
  sort_unstable_by(partial_cmp) differ on 183 of 198 sizes for inputs holding -0.0 / 0.0
  (measured). f64 sorts go through an EXPLICIT comparator. std::max / std::min on doubles
  are refused too (NaN and signed zero). (2) none_of and `find == end` are not rows: they
  are negations (N25 / N26). (3) "accumulate <=> fold" holds only when every element
  converts to the init's type without changing value (or the init is unsigned and wraps):
  `std::accumulate(b, e, 0)` over long longs sums in int (lead 1 confirmed). (4) count /
  count_if are not `.iter().filter(..).count()`: that is usize, and a closure literal in a
  canonical spelling may mention only its own parameters (a user variable named `e` would
  be captured), hence the bx helpers. (5) MISSING: C++ takes the callable by value, so a
  `mutable` lambda advances a copy in C++ but the original in Rust -- refused, naming the
  rewrite. (6) MISSING: Rust's for_each needs a void closure. (7) MISSING: `v.fill(v[0])`
  fails E0502 (measured) while `b.items.fill(b.tag as i64)` compiles, so the check is by
  access path. (8) MISSING: sort / fill / transform-in-place only rewrite elements, so they
  keep an `i < v.size()` loop bound valid; the back_inserter row grows its target and does
  not.

  NARROWINGS: inline lambdas as algorithm arguments are refused (normalizer: bind to a
  local first); a callable PARAMETER is never an algorithm argument; stable_sort with a
  comparator, two-range transform, and comparator forms of max / min / max_element are
  refused. METHOD_RESERVED gains sort, sort_unstable, reverse, fill, contains, extend (a
  struct member function with one of those names is now refused). Census: an `algorithm:`
  needle group in scripts/bx-census.py covers every new wording.
