- [x] FR-265 (opened and SPIKED 2026-11-03, from FR-256's kill criterion and the PMF
  steering log): **HYBRID WEDGE -- AN LLM REWRITES BLOCKED FUNCTIONS INTO THE BX SUBSET,
  CERTIFIED PER FUNCTION BY DIFFERENTIAL EXECUTION: NO-GO AS A PIPELINE STAGE.** The lead
  ("most small blocked functions can be rewritten into the subset, and native-vs-native
  byte-diff catches the rewrites that change behaviour") is half right, and the half that
  is wrong is the one the PMF doc named as the risk: the rewrite becomes a port of the
  module's data model.

  METHOD (evidence archived in docs/pmf/hybrid-2026-11-03/): a pre-registered sample of 20
  of the 274 blocked non-main woff2/brunsli functions with bodies <= 40 lines (sha1 order,
  per module: 2 members/constructors, 3 free functions with 3+ tags, 5 with 1-2 tags),
  frontier record at 4f2a2f5. The rewriter was the spike agent itself, with full repo and
  source access, writing both rewrite and driver -- NOT an independent oracle and not an
  automated pipeline's rate. Certification: original under clang++ ASan/UBSan and g++ -O1,
  rewrite under ASan/UBSan, bx `--normalize` Rust under rustc -O, Rust printed back under
  g++; stdout byte-identical. Extracted functions were compiled in harness TUs only; no
  project build was run.

  MEASURED:
  - Certified on all legs 15/20 = 75% (95% Clopper-Pearson 51%-91%). Gave up 5, all
    non-leaf: ProcessJpeg (the whole decoder), `State::State()` (unique_ptr + destructor +
    brotli handle), TransformFontCollection (~600 lines of callees), Woff2Uncompress and
    the buffer ConvertWOFF2ToTTF (brotli C library; no foreign-call row, no `unsafe`).
  - INTERFACE CHANGES DOMINATE: 11 of the 15 changed a signature (5) or redesigned a type
    the whole module shares (6: woff2 `Buffer`, `BrunsliBitReader`, `Font`'s std::map,
    `GlyfEncoder`). Such a rewrite is usable only once every caller and every user of the
    type is rewritten too, which the per-function certificate does not cover.
  - DROP-IN 4 of 20 (20%, 6%-44%), and none of them needs an LLM: KnownTableIndex (const
    array -> local vector), NextTableBitSize (signed index cast), HuffExtend (DCHECKs
    deleted: no abort row), DecodeLehmerCode (erase -> shift loop). Each is a missing
    Kernel row or a normalizer rule. Upper bound +4 EMIT on 392, halved ~+2; NOT measured
    on the real TUs.
  - bx added no false certificate and miscompiled nothing: on every certified case the
    sanitized rewrite, the Rust and the printed-back C++ agreed.
  - THE ORACLE'S LIMIT, FOUND ON A REAL CASE: EncodeEOI queues a chunk that borrows
    `jpg.tail_data`; the subset cannot store a borrow in a container element, so the
    rewrite copies. The natural driver certifies it; an adversarial driver that mutates
    `tail_data` after queueing diverges on 50/50 lines on all three rewrite legs. The
    byte-diff catches an ownership change only if the driver author thinks to probe it.
  - Injected plausible LLM errors: 17/17 behaviour-changing mutants caught (80%-100%); the 3
    survivors are equivalent on the defined domain (a control, "last" vs "first" over a
    sorted-unique vector, a missing clear observable only through UB).
  - The frontier's blocker sets were lower bounds in 4 of 15 cases (e.g. `vector::erase`
    surfaced only after the listed blocker was cleared) -- as CLAUDE.md §3 says they are.
  Re-verified independently (2026-11-03): cert.sh re-run on HuffExtend, ReadSymbol and
  EncodeEOI natural -- all legs identical, zero `unsafe`; EncodeEOI adversarial diverges;
  the ReadSymbol rewrite read by hand is a genuine port, not a driver artifact.

  GAPS, ranked by FUNCTIONS in the 20-function sample (lower bounds, n=20): non-owning or
  nullable pointers stored in a struct/container 9; classes with private members or a
  constructor body 4; `vector::erase`/`insert` at an index 3; overloading 3 (renaming
  changes public API); null-as-absent (an Option row) 3; std::map 2; foreign library or
  whole-callee closure 4 give-ups; abort/assert row 1; namespace const ARRAY 1 (3 users in
  its module); unique_ptr member + destructor 1. These are Kernel TYPE rows, not rewrites.

  DECISION: do not build the per-function LLM rewrite as a pipeline stage. Keep cert.sh +
  the mutation check as the validation harness for normalizer rules and new type rows.
  NOT TRIED, and what the data points to: a TYPE-FIRST variant (redesign Buffer, BitReader,
  Font, OutputChunk once, then rewrite their users) with a module-level byte-diff on real
  font/JPEG inputs -- its own spike. Expected TRACTOR +0 (no code changed).
