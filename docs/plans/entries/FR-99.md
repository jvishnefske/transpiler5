- [x] FR-99 Nullable owned-FAM returns as `Option<T>` (the session
  coda's ranked-first front — "returned-pointer alloc first" —
  now independently confirmed as the #1 corpus diagnostic: 80 of
  the ranked external blockers carry the `returned-pointer` tag).
  The gap is NOT the owned return itself: FR-94's owned-return
  classification (`famOwnedReturnFns`, ImportCPlanning.cpp:2225-
  2268) already admits `T *f(){ T *p = malloc(...); if (!p)
  return NULL; ...; return p; }` and emits a by-value `-> T`
  with the malloc guard elided. The FIRST gap is the `allPinned`
  clause at ImportCPlanning.cpp:2241-2256: a NULL return that is
  NOT inside an elided malloc guard breaks the classification and
  drops the whole function to the historical returned-pointer
  rejection. That is exactly heatshrink's shape: both
  `heatshrink_encoder_alloc` (heatshrink_encoder.c:76) and
  `heatshrink_decoder_alloc` (heatshrink_decoder.c:57) open with
  a range check returning NULL before they ever call malloc.
  (This entry as first written claimed that clause was the WHOLE
  blocker. It is not — see the SECOND gap in the delivered
  verdict below, which was a latent miscompile, and which is the
  reason the increment is spec-changing rather than a one-clause
  relaxation.)
  The representation: such a function maps `-> Option<T>`, owned
  returns wrap as `Some(place)`, reachable NULLs emit `None`.
  The admitted rule is ANY NON-ELIDED NULL RETURN, not merely a
  leading parameter validation — restated by measurement, see the
  delivered verdict.
  Precedent is established in both directions — FR-88 nullable
  byte-slice params (`Option<&[u8]>`) and FR-96 owned FAM records
  as `Option` MEMBERS — so no new value kind is introduced, only
  a new position for one that exists.
  Call sites (in-TU) admit exactly two shapes: the GUARDED bind
  (`p = f(...); if (p == NULL) ...` folds to the Option test) and
  the UNGUARDED bind (`.unwrap()` — a C null deref is UB, and the
  deterministic panic is this project's accepted refinement
  direction, the argv_arg precedent). Every other call-site shape
  keeps its located rejection; a nullable owned return that
  reaches emission unresolved must fail loudly there, never
  silently unwrap a `None` into a default.
  Frontier stays: returned cursors into caller regions (cJSON's
  `cJSON_GetObjectItem` family) and returned borrows of tree
  nodes — those need the linked-list ownership model and are NOT
  in scope here; they keep the verbatim returned-pointer wording.
  Gates: Import pins (validation-NULL alloc admitted; guarded and
  unguarded call sites; frontier arms — returned cursor, returned
  param, mixed owned/borrowed returns — each still located) +
  EndToEnd byte-diff (an alloc-with-validation program at both
  the accepted and the rejected argument, argc-seeded, vs clang
  native) + external re-probe (heatshrink encoder 23 -> 24/28 and

  **DELIVERED (2026-08-20) — both external targets met, and the
  entry's own gap statement CORRECTED by a second wall the spike
  surfaced.** Two spec-changing findings, both measured:
  (1) THE RULE IS "ANY NON-ELIDED NULL RETURN", not the leading
  parameter validation this entry first scoped. A differential
  probe deleting ONLY the leading validation NULL from both
  heatshrink allocs took the decoder to 13/17 but left the
  ENCODER at 23/28: `heatshrink_encoder_alloc` has a SECOND
  reachable NULL inside the live `if (hse->search_index == NULL)`
  guard, preceded by `HEATSHRINK_FREE(hse, ...)`. Under the
  narrow rule FR-99 would have half-failed its own external gate.
  The generalization is safe because the rest of arm (d) is
  untouched: every non-NULL return must still be an
  `asLoadedLocalVarRef` in `famAllocLocals` and `sawOwned` must
  still hold — an all-NULL function is still not an allocator
  (pinned by the `all-null.c` arm).
  (2) THE CALLER'S GUARD WAS A LATENT MISCOMPILE. `elideGuards`
  (ImportCPlanning.cpp:2098-2122) DELETES `if (p == NULL)` for
  any `famAllocLocals` entry, and arm (b) puts call-bound locals
  in that same map. That is sound only while every callee is
  infallible — which is exactly what FR-99 stops being. Left
  alone, the first nullable callee would have had its caller's
  null check silently deleted: the `None` leg reachable, the
  branch gone. Elision is now conditional on the callee not being
  nullable, and the guard instead folds to `is_none` alongside
  the FR-88/FR-96 arms; FR-94's `CHECK-NOT: cf.cond_br` pin at
  test/Import/C/flexible-array-owned-tail.c:113-129 passes
  unchanged, which is what proves the two paths stayed separate.
  A THIRD gate was added beyond the spec: ADJACENCY — the guard
  must be the statement immediately after the binding, else-less,
  and must not name the local. Without it a non-adjacent null
  test would either fold to the statically-non-null constant (a
  miscompile) or double-move the Option temp; with it, "exactly
  two call-site shapes" is enforceable rather than aspirational,
  and every other null test takes a new located rejection
  ("null test of 'b' outside its binding guard"). The local's
  representation is UNWRAP-AT-THE-BIND (a hidden Option temp; the
  local stays the bare struct), which leaves emitCall's owned-
  argument move, both `famValueLocalQuery` prologues, member
  access and the free-wrapper move untouched.
