  `nix/clippy-eval/LOOP.md` auto-improvement loop): **A C++ CONSTRUCTOR WAS
  NAMED `new`, WHICH IS THE ONE NAME RUST RESERVES FOR THE OPPOSITE THING --
  55% OF THE WHOLE CLIPPY DEBT, FROM ONE LINE.**
  A C++ constructor imports as an INITIALIZER method: it takes the object as
  a receiver and returns nothing, `fn new(&mut self, i: i32)`. Rust's `new`
  is a convention with two hard rules -- it returns `Self` and it takes no
  receiver -- and the emitted method broke BOTH, so default clippy reported
  `new_ret_no_self` AND `wrong_self_convention` on every emitted C++ class.
  METHOD (LOOP.md step 1-2): the ranked tally put the two lints at 64 and 64.

  `"new"` -- mirroring the DESTRUCTOR branch three lines below it, which has

  `ctor` claims no Rust convention and so carries no obligation.
