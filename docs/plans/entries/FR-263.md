- [x] FR-263 (opened 2026-11-01, from FR-252's verification): **BX PRINT ORDER: two
  printing calls unsequenced in one statement are refused.** C++ leaves the order of
  unsequenced operands unspecified (call and printf arguments, `+`, `-`, `<`, ...); Rust
  fixes it left to right. MEASURED: Rust `print!("{} {} {}\n", g(5), g(6), t)` with a
  printing `g` was ACCEPTED and printed as C++ that g++ runs as `g6 g5` and clang/rustc
  as `g5 g6` -- the byte-diff oracle runs clang only and could not see it (same hole
  C++ -> Rust: the input had two legal outputs, the Rust one). FR-252's agent found it;
  FR-252 had closed it for state-modifying closures only.

  RULE (typecheck.py `printing_funcs` / `stmt_alias`): "may print" is a whole-program
  fixpoint by exact path -- a printf, a call of a printing function or member function
  (normalize resolves `MethodCall.owner`), a local closure whose body prints, a callable
  parameter that some call site binds to a printing closure (or to anything that is not
  a local closure: conservative). Two such calls that are SIBLINGS in the unsequenced
  sense are refused (`unsequenced_hits(.., nested_ok=True)`): a call's arguments are
  sequenced before its body, so `outer(g(1), 2)` stays; `&&`, `||`, `?:` sequence their
  operands. Output order is the ONLY effect needed: `T&` arguments are already distinct
  and unmentioned elsewhere in the statement (FR-251 stmt_alias) and the subset has no
  globals. Normalizer named in the wording: evaluate each into a local first.

  EVIDENCE: BX/Reject/print-order.cpp (6 shapes: printf args, `-` with a transitively
  printing callee, two const member calls, a printing closure twice, a template bound to
  a printing closure twice, `<`), BX/Reject/print-order.rs (2); accepted neighbours
  byte-diffed in EndToEnd/bx-print-order.cpp and bx-rs/print-order.rs -- AND checked by
  hand under g++ (three-way identical). gen.py: at most one call per statement
  (constructors exempt, built call-free); the property seeds widened 12 -> 16 instead of
  lowering two coverage pins the stream shift moved by one (over 60 other seeds both
  counts ROSE: move 177 -> 187, internal 96 -> 108). pytest 265/265. Census needle
  `sequencing: two printing calls`. Expected TRACTOR +0; woff2/brunsli EMIT can only
  fall (a new refusal) -- not re-measured.

  NOT COVERED (and why it is safe): the order of two calls that only READ state one
  modifies through `T&` is FR-251's rule; a panic (index out of bounds) in one of two
  unsequenced calls is UB on the C++ side and excluded from the inputs.
