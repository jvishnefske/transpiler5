  THE PLAN'S LEAD WAS WRONG IN THREE PLACES (the spike measured each):
  1. A use is a new node `ConstRef`, NOT a `Var`: a Var is a place, gets moved, and lands
     in a lambda capture list (`[kA]`), which C++ refuses for a non-automatic variable.
  2. Rust cannot shadow a const with ANY binding: `let kA = 7;` with `const kA: i32 = 7`
     in scope is E0005 even for an equal value (re-measured independently, rustc 1.96);
     `let mut` is E0530, a parameter or `for` variable E0005. So a C++ local/parameter/
     loop/lambda variable with a constant's name has no bijective spelling and is refused
     "variable 'k' has the name of a constant" (beside FR-260's function rule).
  3. NO normalizer rule (the planned R5) is needed: at namespace scope `static const`,
     `constexpr` and `inline constexpr` are the same object as `const` (internal linkage;
     `constexpr` is unobservable without array bounds, case labels or template
     arguments), so strict mode accepts all four as one normal form, like N14/N21 for
     functions. normalize.py is unchanged.
  The spike also caught its own prototype printing `crate::ns::kF` for an anonymous-
  namespace constant used outside it (E0603, silently unbuildable); check_visibility now
  covers ConstRef with FR-260's "is internal to namespace" refusal.
